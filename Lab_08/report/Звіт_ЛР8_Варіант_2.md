## 4. Опис REST API

| HTTP method | Endpoint | Призначення | Очікуваний статус |
|---|---|---|---|
| GET | `/books` | Список, фільтрація, пагінація і сортування | 200 |
| GET | `/books/{book_id}` | Отримання книги за ID | 200 / 404 |
| POST | `/books` | Створення книги та, за потреби, автора | 201 / 409 / 422 |
| PATCH | `/books/{book_id}` | Часткове оновлення книги | 200 / 404 / 409 |
| DELETE | `/books/{book_id}` | Видалення книги | 204 / 404 |
| GET | `/authors` | Список авторів | 200 |
| POST | `/authors` | Створення автора | 201 / 409 / 422 |
| GET | `/authors/{author_id}/books` | Книги конкретного автора | 200 / 404 |
| GET | `/books/statistics` | Середня кількість сторінок і найбільша книга | 200 |
| POST | `/authors/batch-books` | Паралельне отримання книг кількох авторів | 200 / 502 / 504 |
| GET | `/health` | Перевірка стану сервісу | 200 |

## 5. Path та query parameters

Приклад path parameter: `GET /books/1`, де `1` — ідентифікатор книги.

Приклад query parameters: `GET /books?author_name=Шевченко&year_from=1800&year_to=1900&page=1&page_size=10&sort_by=pages&order=desc`. Параметри дозволяють фільтрувати за автором і роком, задавати сторінку та кількість результатів, а також сортування.

## 6. Pydantic schemas і правила валідації

`BookCreate` перевіряє назву (1–200 символів), автора (2–120 символів), рік (1–2100), кількість сторінок (1–100000) та необов'язковий ISBN (10–20 символів). `BookPatch` дозволяє передавати лише поля, які змінюються. `AuthorCreate` перевіряє ім'я та біографію. `BatchAuthorsRequest` вимагає список від 1 до 20 унікальних додатних ID авторів. Некоректні дані відхиляються зі статусом 422.

## 7. JSON request і response

Приклад `POST /books`:

```json
{
  "title": "Кобзар",
  "author_name": "Тарас Шевченко",
  "year": 1840,
  "pages": 320,
  "isbn": "9786170000001"
}
```

Приклад відповіді (ID формується базою даних):

```json
{
  "id": 1,
  "title": "Кобзар",
  "year": 1840,
  "pages": 320,
  "isbn": "9786170000001",
  "author_id": 1,
  "author_name": "Тарас Шевченко"
}
```

## 8. Асинхронна частина

`external_api.py` використовує `httpx.AsyncClient` для HTTP GET, `async/await` для очікування відповіді, `asyncio.create_task()` для створення задач, `asyncio.gather()` для паралельного виконання та `asyncio.wait_for()` для timeout. `asyncio.Semaphore` обмежує кількість одночасних HTTP-запитів. При тимчасових помилках повторюються запити з експоненційною затримкою. Кінцева точка `POST /authors/batch-books` запускає агрегування для кількох авторів.

## 9. Persistence layer та архітектура

Використано SQLAlchemy та SQLite. Моделі `Author` і `Book` зберігаються в базі даних. Репозиторії відповідають за запити до БД, сервісний рівень — за бізнес-логіку та обробку конфліктів, API-рівень — за HTTP і статус-коди. Це відповідає ланцюжку `HTTP client → FastAPI → Pydantic → Service → Repository → SQLite`.

## 10. Автоматизоване тестування

Тести перевіряють кореневий endpoint і health check, створення та читання книги, оновлення, видалення, валідацію, конфлікт ISBN, фільтрацію, пагінацію, статистику, авторів, повторні спроби HTTP-запиту й обмеження паралельності. ## 12. Відповіді на контрольні запитання

1. **Що таке комп'ютерна мережа?** Сукупність пристроїв, які обмінюються даними за спільними правилами.
2. **Що таке клієнт-серверна архітектура?** Модель, у якій клієнт надсилає запит, а сервер його обробляє та повертає відповідь.
3. **Що таке HTTP?** Протокол передавання даних між клієнтом і сервером.
4. **Що містить HTTP request?** Метод, URL, заголовки та, за потреби, тіло.
5. **Що містить HTTP response?** Код статусу, заголовки та, за потреби, тіло відповіді.
6. **Для чого GET?** Для отримання ресурсу.
7. **Для чого POST?** Для створення ресурсу або запуску операції.
8. **Для чого PUT?** Для повного оновлення ресурсу.
9. **Для чого PATCH?** Для часткового оновлення ресурсу.
10. **Для чого DELETE?** Для видалення ресурсу.
11. **Що означає 200?** Запит успішно виконано.
12. **Що означає 201?** Ресурс створено.
13. **Що означає 204?** Запит успішний, тіло відповіді відсутнє.
14. **Що означає 404?** Ресурс не знайдено.
15. **Що означає 422?** Дані запиту не пройшли валідацію.
16. **Що таке JSON?** Текстовий формат подання структурованих даних.
17. **Що таке REST?** Архітектурний стиль побудови мережевих сервісів навколо ресурсів.
18. **Що таке resource у REST?** Сутність, доступна за URL, наприклад книга або автор.
19. **Що таке endpoint?** Конкретний шлях API разом із HTTP-методом.
20. **Що таке path parameter?** Значення в самому шляху URL, наприклад `/books/5`.
21. **Що таке query parameter?** Параметр після `?` у URL, наприклад `?page=2`.
22. **Що таке request body?** Дані, які клієнт передає в тілі запиту.
23. **Що таке FastAPI?** Python-фреймворк для створення API.
24. **Для чого Uvicorn?** Для запуску ASGI-застосунків.
25. **Для чого Swagger UI?** Для перегляду документації API та ручного виконання запитів.
26. **Що таке Pydantic?** Бібліотека для опису схем, перевірки та перетворення даних.
27. **Що таке validation?** Перевірка відповідності даних заданим правилам.
28. **Що таке response model?** Схема, яка визначає структуру відповіді API.
29. **Що таке synchronous programming?** Виконання операцій послідовно з очікуванням завершення кожної.
30. **Що таке asynchronous programming?** Підхід, який дозволяє перемикатися між операціями під час очікування.
31. **Для чого async?** Для оголошення coroutine.
32. **Для чого await?** Для асинхронного очікування результату coroutine або awaitable.
33. **Що таке coroutine?** Асинхронна функція/обчислення, виконанням якого керує event loop.
34. **Що таке event loop?** Цикл, який планує та виконує асинхронні задачі.
35. **Що таке Task?** Об'єкт, який планує coroutine для виконання в event loop.
36. **Для чого asyncio.create_task()?** Щоб запланувати coroutine як окрему задачу.
37. **Для чого asyncio.gather()?** Щоб очікувати завершення кількох awaitable-операцій.
38. **Що таке timeout?** Обмеження часу, після якого операція припиняється або завершується помилкою.
39. **Для чого retry?** Для повторення невдалої операції, якщо помилка може бути тимчасовою.
40. **Що таке backoff?** Затримка між повторними спробами, часто зі збільшенням після кожної помилки.
41. **Для чого Semaphore?** Для обмеження кількості одночасних операцій.
42. **Що таке HTTPX?** HTTP-клієнт Python із синхронним та асинхронним API.
43. **Чим AsyncClient відрізняється від синхронного клієнта?** Він виконує HTTP-запити асинхронно й не блокує event loop під час очікування мережі.
44. **Чому AsyncClient бажано повторно використовувати?** Для повторного використання пулу з'єднань і зменшення накладних витрат.
45. **Навіщо обмежувати паралелізм?** Щоб не перевантажувати сервіс, мережу або локальні ресурси.
46. **Чому не запускати тисячі tasks одночасно?** Це може витратити надмірні ресурси та перевантажити зовнішній сервіс.
47. **Як REST API взаємодіє з Repository Layer?** Endpoint викликає сервіс, який використовує репозиторій для читання або зміни даних.
48. **Як FastAPI працює з Pydantic?** Перевіряє request body, формує схеми документації та серіалізує response models.
49. **Як протестувати REST API?** Надсилати тестові HTTP-запити за допомогою FastAPI TestClient або HTTPX і перевіряти статуси та дані.
50. **Чим API integration test відрізняється від unit test?** Integration test перевіряє взаємодію кількох компонентів, а unit test — окрему одиницю ізольовано.
