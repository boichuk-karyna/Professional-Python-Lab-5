# Звіт до лабораторної роботи №9
## Паралельність, багатопроцесність та оптимізація
**Варіант 2 — система обліку книг**

### Мета
Дослідити способи конкурентного та паралельного виконання Python-програми, знайти вузькі місця та порівняти результати базової й оптимізованих реалізацій на великому каталозі книг.

### Предметна область
Книга містить назву, автора, рік видання та кількість сторінок. Реалізовано додавання книги, пошук за автором, фільтрацію за роком, пошук книги з найбільшою кількістю сторінок і середню кількість сторінок. Генератор створює відтворюваний каталог із 100 000 книг за замовчуванням.

### Реалізовані експерименти
1. Послідовна базова статистика на Python loops.
2. Векторизована статистика NumPy з перевіркою еквівалентності результатів.
3. CPU-bound обчислення послідовно, через ThreadPoolExecutor і ProcessPoolExecutor.
4. I/O-bound читання декількох JSON/CSV файлів послідовно та через ThreadPoolExecutor.
5. Синхронізація спільного лічильника потоків за допомогою Lock.
6. Вимірювання часу повторними запусками, оцінка пам'яті через tracemalloc і профілювання через cProfile.
7. Кешування статистики автора та очищення кешу при зміні каталогу.

### Методика
Для кожного benchmark виконується три повтори; у CSV записується середній час. Коефіцієнт прискорення визначається як час базової реалізації, поділений на час відповідного методу. Коректність Python і NumPy статистики перевіряється перед завершенням експерименту. Числа часу залежать від комп'ютера, версії Python і розміру набору даних, тому результати потрібно отримати запуском `python benchmarks/benchmark.py`, а не підставляти прикладні числа.

### Аналіз
Для CPU-bound Python-коду потоки не гарантують прискорення через GIL. Процеси можуть виконувати обчислення на різних ядрах, але мають витрати на створення процесів і передавання даних. NumPy підходить для числових агрегатів завдяки векторизації. Для I/O-bound читання файлів потоки можуть перекривати час очікування. Кешування корисне для повторної статистики незмінних даних, але потребує інвалідації після модифікації каталогу.

### Висновок
У роботі реалізовано профілювання та порівняння способів обробки великого каталогу книг. Проєкт містить базову реалізацію, NumPy, потоки, процеси, синхронізацію, кешування, вимірювання часу й пам'яті, cProfile, тести та формування CSV-таблиці результатів. Остаточний висновок про найшвидший метод потрібно зробити за фактичними вимірюваннями на комп'ютері, де запускається лабораторна робота.
