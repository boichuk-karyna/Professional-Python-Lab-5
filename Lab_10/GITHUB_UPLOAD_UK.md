# Як завантажити всі файли Lab_10 на GitHub (Windows)

GitHub у вебформі завантаження може пропускати приховані файли, назви яких починаються з крапки, наприклад `.env.example`, `.gitignore`, `.dockerignore` та папку `.github`. Не перейменовуйте ці файли: Git і GitHub підтримують їхні назви.

## Рекомендований спосіб

1. Встановіть **Git for Windows**, якщо Git ще не встановлено.
2. Відкрийте GitHub Desktop або Git Bash і клонуйте свій репозиторій на комп'ютер.
3. Скопіюйте папку `Lab_10` з цього архіву до локальної папки репозиторію. Якщо `Lab_10` там уже існує, замініть його вміст файлами з цього архіву, не видаляючи інші лабораторні.
4. Відкрийте папку `Lab_10` усередині клонованого репозиторію.
5. Двічі натисніть `UPLOAD_TO_GITHUB.bat`.
6. Перевірте список файлів, який показує скрипт. Введіть `Y`, щоб створити commit і виконати push.
7. Якщо Git запитає авторизацію, завершіть вхід у GitHub. Якщо push завершився помилкою, збережіть текст помилки.

Скрипт додає звичайні файли та примусово додає `.env.example`, `.gitignore`, `.dockerignore` і `.github/workflows/ci.yml`, навіть якщо вони ігноруються налаштуваннями Git. Він **не** додає справжній `.env` із секретами.

## Важливо

- Не завантажуйте ZIP-архів замість вмісту проєкту: GitHub не розпаковує його як репозиторій.
- Не перейменовуйте `.github` або `.gitignore`: інакше GitHub Actions чи правила ігнорування можуть не працювати.
- Якщо команда `git push` повідомляє про відхилення через нові зміни на GitHub, спочатку синхронізуйте локальний репозиторій; не використовуйте примусовий push навмання.
